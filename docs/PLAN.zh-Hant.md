# 順打 ShunType：0.1 開發與驗收計畫

產品目標是降低標準注音與英文混打時的切換次數，讓輸入保持自然；不能以猜字率換取資料遺失或誤改英文。0.1 是可檢查的本機開發預覽，不宣稱已在所有 App 超越現有輸入法。

## 架構決定

- 原生 Swift / AppKit / SwiftUI，macOS 14 起。第一個交付建置本機 Apple Silicon 版本。
- ShunTypeCore：標準注音按鍵解析、詞頻解碼、多候選、保守的中英判斷、可重現的組字狀態機。
- ShunType：獨立 App，提供真正的互動試打、已打錯文字還原、操作與安裝說明。試打不需全域權限。
- ShunTypeInputMethod：InputMethodKit 輸入法，與試打共用核心。封裝在 App 內，由使用者另行安裝和選用；建置、啟動預覽不會修改系統輸入來源。
- 無全域 event tap、無剪貼簿輪詢、無 Accessibility 自動控制、無雲端推論、無鍵盤歷史紀錄。
- 採用固定上游版本的 McBopomofo 注音映射與詞頻資料；保留授權、來源版本與雜湊。

## 輸入契約

1. 英文與有歧義的字串保留原文。自動模式至少需要完整合法注音、明確的注音線索及足夠音節，才呈現中文。
2. 中文在 marked text 組字區呈現；Enter 提交組字，下一次 Enter 交給原 App。不得代按送出。
3. Esc 提交原始按鍵；退格只編輯尚未提交的組字。Tab / ↓ 在有中文候選時輪換候選。
4. 網址、email、檔案路徑、常見技術字串與大小寫英文採保護規則；保護不是零誤判保證。
5. 不以定時器自動提交或追溯修改已輸入的文件。移動游標、失焦時結束當前組字，不修改新位置。
6. 強制中文與英文模式可用來處理無法僅依按鍵分辨的歧義。保留系統 ABC 與既有輸入法，不攔截使用者主動切換。
7. 原始輸入長度設上限，避免在極長貼上或異常事件中卡住。

## 迭代順序

1. 引擎：取得與檢查資料、建立候選解碼與保護規則，先測正例與反例。
2. 組字：建立與兩個前端共用的狀態機，測試退格、取消、候選、邊界與原文守恆。
3. App：實作可輸入的原生試打區、還原工作台與誠實的安裝狀態。
4. 輸入法：編譯 IMK bundle；用 AppKit 與狀態機測試驗證能驗證的部分。
5. 交付：Release build、核心測試、效能與 App 啟動／互動檢查、封裝 App / ZIP / DMG。

## 驗收與證據界線

- 必須交付可啟動 .app、原始碼、建置指令、授權與資料來源。
- 測試需包含固定中文正例、英文／代碼反例、原始字串復原、組字退格及連續事件；不得只測 UI 示例。
- 測量 warm decode 延遲、冷啟動詞庫時間與包裝大小，保存真實結果。
- 測試框中的輸入不等於已驗證系統 IMK；未啟用輸入法前，LINE / Word / 瀏覽器相容性明列待驗證。
- 簽署、公證與多機／多 macOS 測試是公開穩定版的發布條件；本機 ad-hoc 簽署不能稱為 Apple 公證。
- 不將模擬客戶端或單元測試提升為真實跨 App 接受測試。

## 使用者旅程

開啟 App → 直接試打 → 確認喜歡操作 → 使用者按下安裝輸入法 → 系統鍵盤設定加入並選用 → 先在非重要文字測試。未安裝也可完整使用試打與貼文還原。若系統未刷新第三方輸入法清單，說明可能需登出再登入，不承諾強制刷新。

輸入法啟用是必要前提。若切到 ABC，順打不會處理該輸入。密碼與安全輸入交由 macOS 決定，不試圖繞過。
